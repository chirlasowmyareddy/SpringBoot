The Problem?
generally if we are trying to create an object of another class using new key word in a class then that would be a tight 
coupling
and it future let us suppose Order class became an interface and two child classes came up which are OnlineOrder,
OfflineOrder
and can we do somenting like this
Order order = new OnlineOrder();?

It breaks Dependency injection rule of S.O.L.I.D principle
    -this principle says that DO NOT DEPEND on concrete implemenation,rather depends on abstraction
so fix  this we need to do something like this
public class User{
    Order order;

    public User(Order orderObj){
        this.order= orderObj;//here the extrenal will pass the obj so which follows dependency injection principle
    }
}

So in spring boot this is handled by dependecy injection
-using DI ,we can make our child independent of its dependencies.
-It helps to remove the dependecy on concrete implemenation and inject the dependencies from external source(spring).
though @Autowired spring injects the dependencies
we have three ways to do this
-Field injection
-Setter injection
-Constructor Injection

Field Injection
    -Dependency is set on the fields of the class directly
    -Spring uses reflection ,it iterates over the fields and resolve the dependency.

When we are using qualifier then it breaks the principle of dynamically initializing the bean
so there are 2 approaches
1.using @Qualifier 
    where we autowire the two classes online order and offline order and takes what we need to perform in the reuqest 
    parameter
    boolean isOnlinezOrder

    if(isOnlineOrder){
        onlineOrderObj.createOrder();
    }
    else{
        OfflineOrderObj.createOrder();
    }

    this is the commonly used industry standard
2.@Bean and @Value annotation
    the value comes from configuration files(application.properties),inline literals

    @Configuration 
    public class AppConfig{
        @Bean
        public Order createOrderBean(@Value("${isOrderOnline})" boolean isOnlineOrder){
            if(isOnlineOrder) return new OnlineOrder();
            else return new OfflineOrder();
        }
    }

    so in the class code if Order interface is autowired the spring will check if the component is written if not then it
    checks the configuration files for the bean.and when by seeing application.properties it finaly says what class needs 
    to be used in the code

    in these two ways we can dynamically initialize the beans


@ConditionalOnProperty
bean is created conditionally(mean bean can be created or not)
why?
how can we unclutter the application context with unnecassary beans(imp interview question)**
answer
through this annotation

Interview questions
we want to create only 1 bean either MySQLConnection or NoSQLConnection.(use case is when we are trying to migrate from
to nosql database)

we have 2 components,sharing same codebase,but 1 component need MySQLConnection and other needs NoSQLConnection

@Component
@ConditionalOnProperty(prefix = "sqlconection",value="enabled",havingValue="true",matchIfMissing=false)
public class MySQLConnection{
    MySQLConnection(){
        System.out.println("initializing MySQLConnection bean");
    }
}

@Component
@ConditionalOnProperty(prefix = "nosqlconection",value="enabled",havingValue="true",matchIfMissing=false)
public class NOSQLConnection{
    NoSQLConnection(){
        System.out.println("initializing NoSQLConnection bean");
    }
}

@Component
public class DBConnection{
    @Autowired(required = false)
    MySQLConnection mySQLConnection;

    @Autowired(required = false)
    NoSQLConnection noSQLConnection;

    @PostConstruct
    public void init(){
        System.out.println("DB COnnection  bean created with following dependecies")
        System.out.println("is MySQLConnection object NUll: "+Objects.isNull(mySQLConnection));
        System.out.println("is noSQLConnection object NUll: "+Objects.isNull(noSQLConnection));
    }
}

the prefix and value form the key in the application.properties
sqlconection.enabled=true
required for autowired is mandatory

Advantages
    Toggling of feature
    Avoid cluttering Application Context with un-necessary beans
    Save Memory
    Reduce application Startup time
Disadvantages
    Misconfiguration can happen
    Code complexity when it is over used
    multiple bean creation with same configuration,brings confusion
    complexity in managing

using @Profile annotation, we can tell spring boot,to create bean only when particular profile is set

@Component
@Profile("prod")
public class MySQLConnection{
    @Value("${username})
    String username;

    @PostConstruct
    public void init(){
        System.out.println("MySql username: "+username);
    }
}
//so the bean will not be created
